# 飞书会议语音智能体 PRD

版本：v1.0
日期：2026-08-31
交付截止：2026-09-08
负责人：产品总设计

## 1. 背景与目标

### 1.1 背景

团队需要一个能"坐进"飞书会议的智能体：它听得见会议室里所有人说话，也能开口对会议室所有人说话。操作者用浏览器打开飞书会议网页版（vc.feishu.cn，输入 9 位会议 ID 加入，首次需授权浏览器麦克风，可能有等候室）进入会议室后，智能体接管该浏览器页面的音频：

- 下行：把会议室里的声音实时传给后端，走 ASR → LLM 的理解链路。
- 上行：把后端 TTS 合成的语音注入浏览器，让会议室所有人听到智能体发言。

技术方案已定稿为"方案 C 页面层注入"，本文档只做产品化包装，不推翻、不重议技术选型：

- Playwright 启动 Chrome，通过 `context.add_init_script` 注入 shim.js。
- shim.js 拦截 `navigator.mediaDevices.getUserMedia` / `enumerateDevices`，向页面返回合成麦克风轨（用于上行发声）。
- shim.js 包装 `RTCPeerConnection`，捕获远端音频轨（用于下行收听）。
- 页面内建立 WebSocket 与后端双向传输 PCM 音频（48kHz 单声道）。
- 启动 flags：`--use-fake-ui-for-media-stream`、`--autoplay-policy=no-user-gesture-required`、`--disable-background-timer-throttling`、`--disable-renderer-backgrounding`。
- 验证手段：Chrome 假设备 `--use-file-for-fake-audio-capture`。
- 降级方案：BlackHole 虚拟声卡（两个独立设备，一个当智能体麦克风、一个采集会议声音，从物理路由上防止智能体听到自己）。

### 1.2 目标

到 2026-09-08，交付一个非研发同事可以独立跑起来的会议语音智能体：

1. 智能体能以"参会者"身份进入任意指定飞书会议（9 位会议 ID）。
2. 智能体能实时听到会议室发言，并在会议中开口说话，会议室所有人可听见。
3. 整个系统一键启动，配套配置文件与使用说明文档，其他人拿到后无需研发介入即可跑通。

### 1.3 成功衡量

- 端到端延迟（会议室有人说完话 → 智能体声音在会议室响起）小于 2 秒。
- 无自听：智能体不会听到自己的声音，不产生自我循环。
- 连续运行 30 分钟不掉线、不卡死、音质不劣化。
- 一名未参与研发的同事，仅按使用说明文档操作，能独立完成启动并让智能体入会发言。

## 4. 非目标

以下事项本期明确不做：

1. 不做飞书客户端（桌面端/移动端）接入，仅支持飞书会议网页版 vc.feishu.cn。
2. 不做视频：智能体不开启摄像头，不处理任何视频流。
3. 不做会议内容持久化产品（转写存档、纪要生成 UI 等不在本期范围，后端 ASR 结果仅供 LLM 实时消费）。
4. 不做图形化管理界面，交互以命令行 + 配置文件为准。
5. 不做账号体系与权限管理，系统面向内部受信环境使用。
6. 不解决飞书平台政策层面的合规问题（如平台对自动化参会的限制条款），仅做技术验证与内部试用。
7. 多会议并行（P2-1）本期不做。

## 5. 端到端用户流程

从拿到 9 位会议 ID 到智能体入会通过并发言，操作者视角的每一步：

1. 准备环境：按使用说明文档装好依赖（Python 环境、Playwright 及 Chromium、后端服务依赖），复制配置模板生成自己的配置文件。
2. 填写配置：在配置文件中填入 9 位会议 ID、后端服务地址、ASR/LLM/TTS 所需的密钥，以及（可选）等候室处理方式。
3. 一键启动：在终端执行启动命令。脚本自动完成：以指定 flags 启动 Chrome → 注入 shim.js → 打开 vc.feishu.cn。
4. 加入会议：脚本在页面输入 9 位会议 ID 并点击加入；`--use-fake-ui-for-media-stream` 自动放行浏览器麦克风授权弹窗，无需人工点击。
5. 处理登录态与等候室：
   - 若页面要求登录，终端提示操作者在弹出的浏览器窗口中手动完成登录（首次），登录态由浏览器 profile 保存，后续启动自动复用。
   - 若进入等候室，终端显示"等待主持人放行"，放行后自动继续。
6. 入会成功确认：页面内 shim 捕获到远端音频轨、合成麦克风轨被页面采纳、WebSocket 与后端握手成功，三者齐备后终端打印"智能体已入会"，操作者确认会议室成员列表中出现智能体账号。
7. 收听验证：会议室内任意一人说话，终端出现 ASR 实时转写日志，确认"听"链路正常。
8. 发言验证：操作者触发一次测试发言（或后端主动播报入场语），会议室所有人听到智能体声音，确认"说"链路正常。
9. 正常运行：智能体进入"听到 → 理解 → 回应"循环；操作者通过终端日志观察运行状态。
10. 退出：操作者在终端按 Ctrl+C 或执行停止命令，智能体退出会议、关闭浏览器、断开 WebSocket，资源全部释放。

异常分支：若第 6 步超时（默认 60 秒）仍未齐备，终端输出具体失败环节（音频轨未捕获 / WebSocket 未连接 / 未通过等候室），并指向使用说明文档对应的排查条目。

## 6. 交付形态定义

交付物为一个可整体拷贝的目录，非研发同事拿到后按说明即可运行。具体形态：

| 交付物 | 形态 | 说明 |
| --- | --- | --- |
| 一键启动脚本 | 根目录单个可执行文件（如 `start.command`，macOS 双击或终端执行均可） | 依次完成依赖自检、启动后端、以全部 flags 拉起 Chrome、注入 shim.js、打开会议页并加入会议；任一环节失败给出中文错误提示并指向文档章节 |
| 配置文件 | 单个 `config.json`（附 `config.example.json` 模板） | 字段含：会议 ID、后端地址、ASR/LLM/TTS 密钥、音频参数（默认 48kHz 单声道，非必要不改）、等候室超时、日志级别；每个字段在模板中带中文注释 |
| 使用说明文档 | 根目录 `使用说明.md` | 章节：环境要求 → 安装步骤 → 配置说明 → 启动与验证 → 常见问题排查（含登录态、等候室、无声音、自听、延迟大的处理）→ 卸载与清理。面向零研发背景读者，所有命令可直接复制执行 |
| 验证工具 | `tools/` 下的假设备自测脚本 | 用 `--use-file-for-fake-audio-capture` 在无真实会议的情况下自验上行链路，供使用者排查环境问题 |

运行环境基线：macOS，Python 3.10+，Playwright 1.x + Chromium，稳定的网络。其他平台不承诺支持，文档中注明。

## 7. 验收标准

9/7 验收测试按以下标准逐项核对，全部通过方可于 9/8 交付：

| 编号 | 标准 | 判定方法 |
| --- | --- | --- |
| A1 | 端到端延迟 < 2s | 会议室一人说完一个问句起计时，到智能体回答声音在会议室响起止，连续测 5 次，每次均小于 2 秒 |
| A2 | 无自听 | 智能体发言期间及发言结束后，ASR 不产出来自自身 TTS 内容的转写；连续运行中不出现自我对话循环 |
| A3 | 30 分钟稳定 | 真实飞书会议中连续运行 30 分钟：WebSocket 不断连、音频不中断、无明显音质劣化、内存无失控增长 |
| A4 | 他人可独立跑通 | 指定一名未参与研发的同事，仅使用交付目录与使用说明文档，在其自有环境完成安装、配置、启动，并让智能体成功入会通过且完成至少一轮听说；全程无研发口头指导 |
| A5 | P0 功能齐备 | P0-1 至 P0-4 逐项演示通过 |
