## 1. 背景与被测对象

操作者用浏览器打开飞书会议网页版（vc.feishu.cn，输入 9 位会议 ID 加入，首次需授权浏览器麦克风，可能有等候室）进入会议室；智能体接管该页面的音频：

- **下行**：抽取会议室声音，经 WebSocket 实时回传后端（ASR → LLM）。
- **上行**：把后端 TTS 产出的 PCM 注入浏览器，让会议室所有人听到智能体说话。

**被测对象**（研发交付物，位于 `02-研发实现/`）：

| 交付物 | 作用 | 测试关注点 |
|---|---|---|
| `shim.js` | add_init_script 注入：拦截 getUserMedia/enumerateDevices 返回合成麦克风轨；包装 RTCPeerConnection 抽取远端音频轨 | 与飞书网页版音频管线的兼容性、状态可观测性 |
| `bridge_server.py` | WebSocket 音频桥：下行会议音频 → 后端；上行后端 TTS PCM → 浏览器（48kHz 单声道） | 帧率、断流、重连、时延 |
| `run_agent.py` | Playwright (Python) 启动 Chrome 并入会的主程序（flags 含 `--autoplay-policy=no-user-gesture-required` 等） | 入会流程健壮性、权限/等候室处理 |
| `test_loopback.html` | 链路回环自测页 | 作为 L1 层验证工具本身也要被验证 |
| `README.md` | 使用说明 | TC12「其他人可用性」的直接被测物 |

## 2. 测试目标

1. 验证上行链路（会议室能清晰听到智能体 TTS）与下行链路（智能体能收到会议音频流）功能正确。
2. 验证端到端延迟达标：LLM 出结果 → 会议室听到 < 2s。
3. 验证 30 分钟连续运行稳定性：无断流、无累积延迟漂移。
4. 验证无自听：ASR 转写绝不包含智能体自己的 TTS 内容（无自答死循环）。
5. 验证交付物「其他人可以用」：非研发同事仅按 README 能从零跑通。
6. 输出缺陷清单与验收结论，支撑 9/8 交付决策。

## 3. 测试策略与范围

### 3.1 分层策略

| 层 | 名称 | 手段 | 依赖 | 覆盖用例 |
|---|---|---|---|---|
| L1 | 链路级验证 | Chrome 假设备（`--use-file-for-fake-audio-capture=test.wav`）+ test_loopback.html 回环 | 不依赖真实会议/后端模型 | TC01、TC02 |
| L2 | 真实会议联调 | 真实飞书会议（测试会议号），仅验证入会与下行 | 飞书网页版 | TC03、TC07、TC08、TC14 |
| L3 | 全链路 | 接入后端 ASR→LLM→TTS，双人听说 | L2 通过 + 后端就绪 | TC04、TC05、TC10、TC11 |
| L4 | 稳定性/异常/可用性 | 30 分钟长跑、弱网、循环入会、非研发可用性 | L3 通过 | TC06、TC09、TC13、TC12 |

**原则**：每一层出问题先在该层用最小复现定位，不带病进入下一层；L1 结论不外推（假设备与 shim 注入是两条不同路径，见风险 R2）。

### 3.2 测试范围（In-Scope）

- 音频上行：TTS PCM 注入 → 飞书会议 → 远端参会者收听（内容正确、清晰、不截断）。
- 音频下行：会议远端音频抽取 → WebSocket 回传 → ASR 转写（帧连续、格式 48kHz 单声道）。
- 入会流程：9 位会议 ID 加入、首次麦克风权限、等候室、主持人静音/解除。
- 全链路质量：10 轮对话成功率、端到端延迟、打断/双讲行为、无自听。
- 健壮性：30 分钟稳定性、弱网/断线重连、反复入会退出、异常会议 ID。
- 交付可用性：README 完整性、非研发同事独立跑通。

### 3.3 测试环境

| 项 | 约定 |
|---|---|
| 机器 | Mac A（跑 run_agent.py + bridge_server.py + 后端）；Mac B（第二参会端，监听+录音）。两机时钟用 ntp 对时 |
| 系统 | macOS 13+（记录具体版本）；系统「麦克风/自动化」权限预授权 |
| 浏览器 | Chrome 固定版本（测试期间不升级，版本号记入测试报告） |
| 自动化 | Python 3.11+，Playwright (Python)，依赖版本锁定 |
| 飞书 | 测试企业账号 2 个（主持人 + 第二参会人）；测试会议每日新建 |
| 弱网工具 | Network Link Conditioner 或 CDP `Network.emulateNetworkConditions` |
| 测试素材 | `test.wav`（48kHz/16bit/mono/10s：1kHz 导频 1s + 朗读句「测试一二三，智能体上行验证」）；`inject_10s.pcm`（48kHz/16bit/mono，1kHz 正弦 3s + 朗读「下行回环测试」）；2 分钟朗读稿（含数字、英文、专有名词）；10 条提问清单 |
| 日志约定 | bridge_server / run_agent / 后端日志统一毫秒时间戳 + trace_id；每次执行记录代码 commit、Chrome 版本、会议号 |

## 4. 缺陷分级标准

| 级别 | 定义 | 示例（本项目语境） | 响应/修复时效 | 流程影响 |
|---|---|---|---|---|
| **P0 阻塞** | 核心音频链路完全失效，或破坏会议正常进行，且**无临时绕行方案** | ① TTS 注入后会议室完全听不到声音；② 下行抽不到远端音频轨（帧计数为 0）；③ 入会即页面崩溃/浏览器退出；④ ASR 转写到智能体自己的 TTS 形成自答死循环 | 当日响应、24h 内修复 | 阻塞当前阶段退出；发现即暂停相关用例并通报 |
| **P1 严重** | 核心功能受损或重要场景失效，但**有临时绕行**；或关键指标不达标 | ① 打断失效（TTS 盖过人声）；② 端到端延迟 ≥2s；③ 断线重连后无声需手动刷新；④ 30 分钟内出现可自动恢复的断流；⑤ 权限弹窗每次需人工点击；⑥ 非研发按 README 跑不通（阻塞型卡点） | 48h 内修复 | 交付前必须清零，或经三方评审书面豁免 |
| **P2 一般** | 边缘场景、体验类问题，不影响主链路 | ① 极端弱网下轻微卡顿可自愈；② 日志时间戳精度不足；③ README 个别措辞不清但可猜对；④ 偶发无害告警日志 | 记录排期 | 可带问题交付，但须在验收 checklist 中逐项标注 |

补充约定：
- 文档/可用性类缺陷单独标注「类型=文档」，级别同样适用；TC12 的卡点默认至少 P2，导致无法继续的升 P1。
- 级别判定有争议时按「就高不就低」，三方对齐会上最终裁定。
- 豁免的 P1/P2 必须记录：豁免原因、影响面、后续跟踪人。

## 6. 风险与豁免项

### 6.1 风险登记

| ID | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | 飞书网页版升级导致 UI 结构/音频管线变化，shim.js 假设失效 | 中 | 高 | 每日开工先跑入会冒烟；Chrome 固定版本；shim 失败时保留页面快照与 console 日志便于快速定位 |
| R2 | 假设备路径与 shim 注入路径不同：TC01 通过不代表 TC04 上行可用 | 高 | 高 | 计划内分两阶段验证（L1 与 L3），TC01 结论不外推；TC04 失败时优先排查 getUserMedia shim 与飞书音频发送管线的兼容性 |
| R3 | 等候室依赖主持人放入，无人值守时流程卡住 | 中 | 中 | 测试会议主持人账号由测试组持有；入会脚本设超时（60s）告警；主持人端尽量自动化或专人值守 |
| R4 | 外部服务（ASR/LLM/TTS）配额或网络不稳定，拖慢 S3 | 中 | 中 | 提前确认配额；准备降级方案（固定文案 mock LLM）先测通链路，再恢复真实模型 |
| R5 | 30 分钟稳定性若发现累积漂移，定位成本高 | 中 | 中 | 提前埋点：每 5 分钟自动延迟探针 + 资源采集，问题出现即有时序数据 |

| R7 | 排期紧张：S2/S3 任一延期将挤压 S4 | 中 | 高 | 9/5–9/6 周末机动；延期超 1 天启动降级预案（见 6.3） |

### 6.2 豁免项（明确不测）

| 项 | 说明 |
|---|---|
| 浏览器兼容性 | 仅 Chrome；Safari/Firefox/移动端不测 |
| 飞书客户端 | 仅网页版 vc.feishu.cn；飞书 App/桌面客户端入会不测（B 端监听可用 App，属测试工具非被测对象） |
| ASR 准确率评测 | 仅做功能性抽样（关键词命中率），不做大规模语料标注评测 |
| TTS 音色/自然度 | 主观调优属模型效果，不在本次功能测试范围 |
| LLM 回答内容质量 | 只验证「能答、听得清」，不评估回答好坏 |
| 安全/渗透测试 | 豁免 |
| 大型会议压力 | 测试会议规模 ≤6 人；百人大会不测 |

### 6.3 降级预案

若 9/3 联调或 9/4 全链路延期超过 1 天：
1. P2 用例（TC13、TC14）移至交付后补测；
2. TC12 缩减为 1 名非研发同事；
3. TC06 30 分钟稳定性**不缩减**（质量底线），必要时占用 9/8 上午；
4. 预案启动需三方对齐会确认并记录。
