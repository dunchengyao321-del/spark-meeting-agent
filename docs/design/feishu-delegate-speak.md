# 飞书会议「代我发言」智能体 · 设计方案

> 版本：v1.1（全部决策已确认，进入实施） · 日期：2026-08-27
> 前置文档：`docs/design/meeting-voice-agent.md`（会议语音智能体总体设计，本方案对应其 P4「飞书实战」阶段）
> 定位：让星火以**你的身份**进入真实飞书会议，听得懂会中讨论，按你的意图**发声发言**，全程可控、可审计。
>
> **v1.0 定稿**：首批称呼枚举定为「张三 / 三哥 / 张张 / alex / 张老师」；缓冲句定稿「好的，我看一下」；音色定为火山现有音色 `zh_male_wennuanahu_uranus_bigtts`（公开音色，无需声纹复刻授权）；待确认清单会后 IM 私聊你本人；多会议并行旁听确认不做。
> **v1.1 修订**：入会约束放宽——**只要你明确要求即可入会**，账号互挤仅提示、不拦截；TTS 降级链移除 OpenAI TTS（代码库已删除该引擎），链为 火山 TTS → macOS say；火山配置字段对齐代码现状（`volcano_tts_api_key` / `volcano_tts_speaker`）。**无遗留待确认事项，可进入 P4.0 实施。**

## 1. 目标与能力边界

### 1.1 「代替我说话」的完整含义

| 维度 | 设计承诺 |
|------|----------|
| 身份 | 以**你本人的飞书账号**入会（复用 `~/.spark/feishu-profile` 登录态）；昵称「AI 代」后缀为可选项，默认关闭 |
| 入会方式 | **你主导入会**：你在智能体托管的浏览器里自行加入目标会议，再把会议信息发给智能体绑定（§4.1），智能体不主动闯会 |
| 声音 | 火山 TTS，音色 `zh_male_wennuanahu_uranus_bigtts`；降级链：火山 TTS → macOS say（OpenAI TTS 已从代码库移除） |
| 内容 | 三级来源：你的实时指令 > AI 生成 + 你确认 > 白名单场景自动应答 |
| 人设 | **专业产品经理**：只提供专业产品建议与问题解答；禁止闲聊、脏话、与工作无关话题（§6.5 守门机制） |
| 听觉 | 会中声音实时转写；**被提及你的名字**（枚举：张三 / 三哥 / 张张 / alex / 张老师）能接住 |
| 答不了 | 会中发「记录」话术兜底，写入待确认清单，会后 IM 私聊转告你（§6.6） |
| 可控 | 每条自动发言可审、可打断、可一键闭麦；全程留痕可回放 |

### 1.2 明确不做的事

- 智能体不主动入会：入会动作永远由你发起；**只要你明确要求，即可入会**——包括你账号疑似在其他设备入会的情况，系统仅提示互挤风险、不拦截（§10）；
- 不做高 stakes 承诺：涉及报价、人事、法务结论的话题一律转人工（§6.4）；
- 不在会中闲聊：与会议议题无关的内容，守门机制直接拦截；
- **不做多会议并行旁听**（已确认）：单会议绑定 + 「换会」切换。

### 1.3 单会议约束（已确认）

- **发言**：同一时刻只能绑定**一个**会议（你的账号唯一在线 + BlackHole 单音频通道的物理约束）；
- **监听**：单会议绑定，支持「换会」指令快速切换；
- 多会议并行旁听本阶段不做、亦不列入后续规划。

## 3. 技术路线选型

### 3.1 两条路线对比

| | 路线 A：浏览器桥接 + BlackHole | 路线 B：官方 VC Agent API |
|---|---|---|
| 原理 | Playwright 以你的登录态入会，TTS → BlackHole 虚拟麦克风发声；会议声音回采 → ASR | `lark-cli vc +meeting-join` 机器人入会，`+meeting-events` 拉结构化事件，`+meeting-message-send` 发会中文字 |
| 发言形式 | **真实语音**（TTS 出声） | 仅会中文字消息 / 表情，**无语音能力** |
| 会议感知 | 音频 → ASR 转写（无说话人标签，靠声纹） | 结构化事件：转写、聊天、进出会、共享，**自带 actor 标签** |
| 身份 | 你本人账号（**已选定**） | 应用机器人（会中显示为机器人参会） |
| 可用性 | 今天就能用 | 内测审批中（已申请，待飞书回复） |
| 稳定性 | 中：依赖浏览器自动化与页面 DOM，飞书改版可能失效 | 高：官方 API |
| 多会议 | 单会（账号唯一在线 + 单音频通道） | 机器人可同听多会（仅听 + 文字） |

### 3.2 选型结论：A 为主、B 为辅的混合架构

- **发声只走 A**：官方 API 不支持音频注入，「说话」必须走 BlackHole 桥接；
- **感知 A/B 双源**：A 的 ASR 是通用兜底；B 批复后其结构化事件（带说话人标签的转写）作为**更高质量感知源**，直接省掉声纹分离最难的部分；
- **B 的文字消息做兜底**：音频链路故障时降级为会中文字发言并告警；
- **B 当前状态**：内测已申请待批复，P4.3 挂起；感知源是抽象接口（§4.4），A-only 即可完整运行，不阻塞 P4.0–P4.2、P4.4。

## 4. 总体架构

### 4.1 会议绑定流程（你主导入会）

```
1. 启动智能体托管浏览器（Playwright，复用 ~/.spark/feishu-profile 登录态）
2. 你在该浏览器中自行加入目标会议          ← 入会动作由你完成，杜绝误入错会
3. 你把会议信息发给智能体：IM「绑定会议 123456789」或控制台输入会议号
4. 智能体校验托管浏览器确在该会中 → 绑定成功 → 开始监听与待命
5. 会中：「换会 <会议号>」解绑并绑定新会；「退场」停止工作（浏览器仍由你控制）
```

绑定校验：读取托管浏览器当前会议页面的会议号，与你发送的会议号比对，一致才绑定；不一致则拒绝并提示当前实际所在会议。

### 4.2 架构图

```
                        ┌──── 你的控制通道 ────────────────────────────┐
                        │  飞书 IM（bot_listener）│ 8765 控制台指令台    │
                        │  绑定会议/说:/ai:/闭麦/换会/退场/审批           │
                        └──────────────┬──────────────────────────────┘
                                       │
┌──────────────────────────────────────▼──────────────────────────────────┐
│                    server/ 会议大脑（复用 8765 管线）                      │
│  会议感知 → 转写流 ──► 轮次仲裁（提及名称枚举）──► 对话引擎                │
│     ▲                  │              (产品经理人设+KB+MCP+style_profile) │
│     │                  │                     │                          │
│     │            发言审批器(§6.3)      行为守门(§6.5) ──► TTS(火山指定音色)│
│     │                  │                     │                          │
│     │            待确认清单(§6.6)      发言留痕日志                        │
└─────┼──────────────────────┬─────────────────────┬──────────────────────┘
      │ 会议声音回采          │ TTS 音频              │ 会中文字(可选,待内测)
┌─────┴──────────────────────▼─────────────────────▼──────────────────────┐
│                 integrations/feishu/ 桥接层（新增适配器）                  │
│  A: meeting_voice_host 重构版 ── 托管浏览器 + BlackHole 双向音频           │
│  B: vc_agent_client（挂起待批复）── lark-cli vc 包装：事件/文字/离会        │
└─────────────────────────────────┬───────────────────────────────────────┘

```

三层解耦不变：**大脑（server/）不感知飞书细节**，桥接层对大脑只暴露两个接口——`meeting_audio_in`（会中听到什么）与 `meeting_say`（往会里发声/发字）。未来换会议平台只动桥接层。

### 4.3 音频路由设计（路线 A 核心）

```
TTS 输出 ──► BlackHole 2ch（虚拟麦克风）──► 飞书「麦克风」选中 BlackHole ──► 会中其他人听到
会议声音 ──► 多输出设备(BlackHole + 扬声器) ──► ffmpeg 回采 BlackHole ──► server/ ASR 管线
                                                       └──► 扬声器：你旁听用（可静音）
```

- 复用现有 `detect_blackhole_index()` + SwitchAudioSource 切换逻辑；
- **防自激（关键）**：TTS 播放期间开启「自屏蔽窗口」暂停回采声道 ASR（沿用总体设计 §5.4），并在轮次仲裁里把「自己刚说的话」从转写流中剔除；
- 设备索引不稳定问题（现有代码注释已标注）：启动时校验 + 运行中心跳检测，路由漂移自动重校准并告警到控制台。

### 4.4 会议感知抽象（A/B 双源）

```python
class MeetingPerception:  # integrations/feishu/perception.py
    def transcript_stream(self) -> Iterator[Utterance]: ...
    # Utterance: {speaker_label|None, text, is_final, source: "asr"|"vc_event", ts, conf}
```

- **ASR 源（默认）**：回采音频 → 流式 ASR → 声纹匹配（常驻参会人注册制，复用 P2 成果）；
- **VC 事件源（内测批复后启用）**：机器人同会旁听，每 10–15s 增量拉 `+meeting-events --page-all`，转写事件直接产出带 actor 标签的 Utterance，**免 ASR、免声纹**；用 `page_token` 续拉；
- 双源同开时以 VC 事件为准、ASR 补延迟盲区；仲裁器只消费统一 Utterance 流。

### 4.5 发言通道抽象

```python
class MeetingSpeaker:
    def say_voice(self, text: str) -> bool   # A: 火山 TTS（zh_male_wennuanahu_uranus_bigtts）→ BlackHole
    def say_text(self, text: str) -> bool    # B: 会中文字消息（兜底，待内测）
    def react(self, emoji_type: str) -> bool # B: 会中表情（轻反馈，待内测）
```

降级链：`say_voice` 失败（火山密钥/配额/网络异常）→ 自动降级 macOS say 出声（不冷场）；音频链路整体故障时，内测开通后自动 `say_text` 同内容，未开通时直接 IM 告警给你人工接管。

## 5. 会中行为策略

发言触发优先级（高 → 低）：

| # | 触发 | 说明 | 默认动作 |
|---|------|------|----------|
| 1 | 你的实时指令 | IM「说：…」「ai:…」或控制台指令台 | 直接发声，最高优先，可打断进行中的自动发言 |
| 2 | **提及你的名字** | 转写中出现提及名称枚举，且上下文为称呼/问句/移交（如「三哥你怎么看」） | 立即发**缓冲句**（「好的，我看一下」）→ AI 起草 → §6.3 审批 → 发声 |
| 3 | 被直接提问 + 静默 2s | 问句指向你（含枚举名称）且无人接话 | 同上；任何人开口立即让路 |
| 4 | KB 高命中事实问答（白名单） | 事实型问题且检索置信度 > 阈值 | AI 起草 → §6.3 审批 → 发声 |
| 5 | 其余时间 | 只听、转写、预热上下文、写纪要 | 不发声 |

### 5.1 提及名称枚举（核心配置）

- **首批枚举值（已定稿）**：`["张三", "三哥", "张张", "alex", "张老师"]`；
- 匹配规则：大小写不敏感（alex / Alex / ALEX 均命中）；**最长优先去重**——命中「张三」不再重复计「三哥」，同一句多次命中只触发一次；
- 维护方式：控制台设置页编辑，或 IM 指令「添加称呼 xx」「删除称呼 xx」「查看称呼」；
- 判定逻辑：转写文本命中任一枚举值 **且** 满足以下任一上下文条件——(a) 名称后为问句/请求句式；(b) 名称独立成称呼（「三哥，…」开头）；(c) 移交话术（「让张老师说一下」）。仅提到名字但语境与你无关（如转述「三哥之前说过…」）不触发；
- 误报兜底：误触发时你随时可 IM「闭麦」或打断，留痕用于优化判定。

多人重叠说话 → 继续监听并标注「讨论中」，不插话。

## 6. 发言内容、审批与守门

### 6.1 内容三级来源

1. **指令原文**（你说什么它说什么）：`说：大家好，我网络不好` → 原样 TTS；
2. **AI 生成 + 确认**（`ai:` 指令或被点名时）：LLM 结合会议转写上下文 + KB/MCP + `style_profile` + 产品经理人设起草 → 走 §6.3 审批；
3. **白名单自动应答**：仅 §6.2 两项。

### 6.2 自动发言白名单（定稿，仅两项）

| 场景 | 话术/逻辑 | 状态 |
|------|-----------|------|
| 被提及名字时的应答缓冲 | 「好的，我看一下」（**已定稿**；争取 3–5s 生成时间） | 默认开启 |
| KB 高命中事实问答 | 检索置信度 > 阈值且问题为事实型，答案附出处 | 默认开启；阈值先取默认值，演练中调优 |

无入会开场白、无到点提醒（已按你的决定移除）。

### 6.3 审批流

```
触发发言 → 缓冲句先行（被点名场景）→ AI 起草（带上下文依据）
   ├─ 控制台：确认卡（草稿全文 + 引用来源），快捷键 确认/改后发送/丢弃
   └─ 飞书 IM：推送草稿给你，回复「发」发出；回复修改意见则重起草
        60s 未回复 → 按场景默认：被点名/移交类 → 已发缓冲句，正式回答超时丢弃并 IM 提醒你
                     KB 问答类 → 直接丢弃（不强行回答）
```

### 6.4 敏感话题兜底

起草内容命中敏感类别（报价/承诺/人事/法务/未公开路线图，关键词 + LLM 双判）→ 不自动发，改发缓冲句「这个点我需要确认一下，会后回复大家」，同时 IM 升级提醒你人工接管，并自动记入待确认清单（§6.6）。**说错话的成本远高于少说话。**

### 6.5 人设与话题守门

- **人设**：系统提示词固定为「你是一名专业产品经理，代表主人在会中发言。只提供专业的产品建议与问题解答；禁止闲聊、脏话及任何与工作无关的话题；回答简明、有结论、有依据。」
- **双保险**：
  1. *生成时约束*：上述人设进 system prompt，KB/MCP 上下文一并注入；
  2. *发送前守门*：每条待发内容（含你的 `ai:` 指令产物）过一道轻量分类器——命中「闲聊/脏话/无关话题」直接拦截：自动发言改写为专业回应或沉默；指令产物退回并 IM 告知拦截原因；
- 会中被问及无关话题（如闲聊提问点名到你）→ 标准应对：「这个我们会后单独聊，先聚焦会议议题。」

### 6.6 「答不了 → 记录 → 会后转告」闭环

- **触发**：KB 无命中且模型低置信，或问题需要你本人决策/掌握的信息；
- **会中话术**：「这个点我记下来了，确认后回复大家。」（避免现场硬答）；
- **记录**：写入「待确认清单」——问题原文、提问人（有说话人标签时）、上下文转写片段、时间戳；
- **会后转告（已确认）**：会议结束（你发「退场」或检测到会议结束）后，自动把待确认清单 + 发言留痕摘要通过**飞书 IM 私聊你本人**；
- 你在 IM 回复答案后，可指令「把第 2 条回复发到会议群/原会聊天」完成闭环。

## 7. 控制通道与会中可见性

- **IM 指令集**（复用 bot_listener 扩展）：`绑定会议 <9位号>` / `换会 <9位号>` / `退场` / `说：…` / `ai:…` / `闭麦` / `开麦` / `状态` / `添加称呼 xx` / `删除称呼 xx` / `待确认`（随时查看当前清单）；
- **控制台会中视图**：实时字幕流（带说话人）、智能体状态灯、当前绑定会议号、待审批草稿卡、「立即打断」大红按钮、发言留痕时间线、待确认清单；
- **留痕审计**：每轮 `触发来源 → 草稿 → 守门结果 → 审批结果 → 实际发出内容/音频` 全量落盘（本地 SQLite），会后纪要自动附带「AI 代发言清单 + 待确认清单」。

## 8. 合规说明

- 按你的决定：**无入会开场白、无强制披露话术**；是否向参会者说明 AI 辅助由你按场合自行把握（建议重要会议口头知会一声，降低误会产生时的解释成本）；
- 会议录制/转写遵守公司制度；留痕日志仅存本地，不入库不上传;
- 音色使用火山引擎**公开音色**（非声纹复刻），无需本人录音授权；仓库只保存音色标识（`volcano_tts_speaker`），火山密钥仅存本地 `config.json`，不入库不外传。

## 10. 风险与对策

| 风险 | 对策 |
|------|------|

| 回声/自激（智能体听到自己） | 自屏蔽窗口 + 转写去重 + 多输出设备正确配置；§4.3 心跳检测 |
| BlackHole 设备索引漂移 | 启动校验 + 运行中重校准（现有代码已标注该不稳定点，本方案补自动恢复） |

| 火山 TTS 密钥/配额异常 | 自动降级 macOS say 出声，不冷场（TTS 工厂仅 `say` / `volcano` 两引擎，OpenAI TTS 已移除） |
| 内测批复不确定（路线 B） | 架构不依赖 B：P4.0–P4.2、P4.4 全部可交付 |
| AI 说错话 | 三级内容来源 + 审批默认开启 + 守门拦截 + 敏感兜底 + 全程留痕可追责 |
