## 附：Bug 报告模板

提交位置：`03-测试/bugs/`（每个 Bug 一个 md 文件，命名 `BUG-<序号>-<简述>.md`）。

| 字段 | 填写说明 |
|---|---|
| BugID | BUG-YYYY-NNN（如 BUG-0901-001） |
| 标题 | 一句话：什么场景 + 什么现象（例：断网恢复后 TTS 无声需手动刷新） |
| 级别 | P0 / P1 / P2（定义见测试计划 §4，争议时就高） |
| 类型 | 功能 / 性能 / 稳定性 / 文档 / 可用性 |
| 关联用例 | TC 编号（探索性发现填「无」） |
| 环境 | 代码 commit、Chrome 版本、macOS 版本、会议号、网络条件 |
| 前置条件 | 复现前必须满足的状态 |
| 复现步骤 | 编号步骤，最小复现优先 |
| 实际结果 | 现象 + 关键日志摘录（带毫秒时间戳与 trace_id） |
| 预期结果 | 对应用例预期或设计声明 |
| 复现概率 | 必现 / 高频(≥50%) / 偶发(<50%)，附尝试次数 |
| 附件 | 双端录音、页面截图/录屏、console 日志、WebSocket 帧日志 |
| 临时绕行 | 有/无；有则写明操作步骤 |
| 负责人 | 研发接口人 |
| 状态 | 新建 → 已确认 → 修复中 → 待验证 → 关闭 / 豁免（豁免需三方签字） |

**示例（一行版）**：

> BUG-0904-002｜标题：真人打断后 TTS 残余句继续补播约 2s｜P1｜功能｜TC05｜commit a1b2c3 / Chrome 129 / 会议 123456789｜步骤：TTS 开播 3s 后 B 端说话｜实际：TTS 未停且补播残余句（日志 12:03:04.512 起 2.1s）｜预期：≤1s 停止且不补播｜复现：3/3 必现｜附件：B 端录音+bridge 日志｜绕行：无｜状态：新建
